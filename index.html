Installation

hxjavascript has zero runtime dependencies and works on Haxe 4.2 and above. Choose an install method below.

shell — via git (recommended)
haxelib git hxjavascript https://github.com/Brenninho123/hxjavascript
shell — via haxelib (once published)
haxelib install hxjavascript

Add the library to your build.hxml:

hxml
-cp src -lib hxjavascript -js bin/app.js -main Main
⚠
JS target only. Every module guards itself with #if !js #error #end. Attempting to compile for cpp, hl, neko or any non-JS target will produce a compile-time error.

First JS Call

The JS module provides direct runtime access to the JavaScript engine. All methods are inline and compile to zero-overhead native expressions.

haxe
import hxjavascript.JS; class Main { static function main() { var sum:Int = JS.eval("1 + 2 + 3"); JS.run("document.title = 'Hello from Haxe'"); JS.globalSet("myLib", { version: "1.0" }); var lib = JS.globalGet("myLib"); var t:String = JS.typeof(42); var json:String = JS.stringifyJSON({ x: 1, y: [2,3] }, 2); } }
ℹ
eval() and CSP. JS.eval() calls the browser's native eval. If your deployment uses a Content Security Policy that disallows eval, use JS.run() instead — it wraps the code in new Function() which may be permitted under a unsafe-eval or wasm-unsafe-eval directive.
  • JS.eval<T>(code) — evaluates an expression and casts the result to T
  • JS.run(code) — executes a statement, no return value, isolated scope
  • JS.globalGet / globalSet — read/write window properties by name
  • JS.exists(name) — checks if a global exists without throwing
  • JS.parseJSON / stringifyJSON — typed JSON roundtrip

Dynamic Objects

JSObject wraps any JS value in a typed interface. This avoids scattering untyped calls through your codebase while keeping Haxe's type checker happy.

haxe
import hxjavascript.JSObject; var obj = JSObject.from({ name: "Haxe", version: 4, tags: ["typed", "cross"] }); obj.get("name"); obj.set("version", 5); obj.has("tags"); obj.delete("tags"); obj.keys(); obj.values(); obj.toJSON(2); var arr = JSObject.array(); arr.call("push", ["a", "b"]); arr.get("length"); var raw:Dynamic = obj.unwrap();
✔
call() pattern. Use call(method, args) to invoke any JS method on the wrapped object. It expands to obj[method].apply(obj, args) — preserving the correct this context.

HTTP Requests

The Fetch and Promise modules work together. Fetch returns a Promise<FetchResponse> which you chain to read the body.

haxe — GET request
import hxjavascript.Fetch; Fetch.get("https://api.example.com/users/1") .then(r -> { var status:Int = r.status; var ok:Bool = r.ok; return r.json(); }) .then(data -> { var name:String = data.name; }) .catchError(e -> trace(e));
haxe — POST with JSON body
Fetch.post( "https://api.example.com/users", { name: "Brenninho", role: "dev" }, { "Authorization": "Bearer TOKEN" } ) .then(r -> r.json()) .then(data -> trace(data.id)) .catchError(e -> trace("Network error:", e));
haxe — Promise combinators
import hxjavascript.Promise; var p1 = Fetch.get("/api/a").then(r -> r.json()); var p2 = Fetch.get("/api/b").then(r -> r.json()); Promise.all([p1, p2]) .then(results -> { var a = results[0]; var b = results[1]; }) .finally(() -> trace("Done"));

Web Workers

Use Worker to offload heavy computation to background threads. Messages are typed via the JSObject pattern.

haxe — main thread
import hxjavascript.Worker; var w = new Worker("bin/worker.js"); w.onMessage(msg -> { var result:Int = msg.data.result; trace("Worker result:", result); }); w.onError(err -> { trace("Worker error:", err.message); }); w.post({ action: "compute", value: 1_000_000 }); // Transfer ArrayBuffer ownership (zero-copy) var buf = JS.eval("new ArrayBuffer(1024)"); w.post({ data: buf }, [buf]); w.terminate();
javascript — worker.js (browser-side)
self.onmessage = function(e) { if (e.data.action === "compute") { var n = e.data.value; var sum = 0; for (var i = 0; i < n; i++) sum += i; self.postMessage({ result: sum }); } };
ℹ
ES Module workers. Pass { type: "module" } as the second argument to use ESM syntax inside the worker: new Worker("worker.js", { type: "module" }).

Storage

Storage.local and Storage.session give typed access to the Web Storage API. Both support string and JSON object persistence.

haxe — string values
import hxjavascript.Storage; Storage.local.set("username", "Brenninho"); var name = Storage.local.get("username"); Storage.local.remove("username"); Storage.local.clear(); var keys:Array<String> = Storage.local.keys(); var len:Int = Storage.local.length();
haxe — JSON objects
typedef Config = { theme:String, lang:String, fontSize:Int } Storage.local.setObject("config", { theme: "dark", lang: "pt-BR", fontSize: 14 }); var cfg:Null<Config> = Storage.local.getObject("config"); if (cfg != null) { var theme:String = cfg.theme; } Storage.session.set("token", "eyJhbGci...");

Compile-time Macros

The JSMacro build macro auto-generates typed property accessors for fields annotated with @jsProperty. The result is zero-cost: no runtime object, just untyped __js__ reads and writes.

haxe — extern class with @jsProperty
import hxjavascript.macro.JSMacro; @:build(JSMacro.buildExtern()) class MyLib { @jsProperty public static var version:String; @jsProperty public static var debug:Bool; @jsProperty public static var maxRetries:Int; } class Main { static function main() { var v:String = MyLib.version; MyLib.debug = true; MyLib.maxRetries = 3; } }
⚠
Macro target restriction. The macro itself compiles under #if macro. The generated accessors are #if js guarded, so the same extern class can live in a multi-target codebase — non-JS targets simply won't compile the field accessors.

Build Pipeline

hxjavascript ships a two-stage build system: Build.hx compiles and packages the Haxe side, Build.js post-processes the output into CJS, IIFE and ESM bundles.

shell — common Build.hx tasks
haxe --run Build all # clean → compile → lint → test → package haxe --run Build compile # compile only haxe --run Build test # compile + run via node haxe --run Build lint # static analysis (trace, comments, line length) haxe --run Build watch # file watcher (polling) haxe --run Build --release all # DCE full + ES6 target
shell — common Build.js tasks
node Build.js all # full pipeline node Build.js bundle # IIFE + CJS with banner node Build.js minify # minify CJS output (+ terser if installed) node Build.js esm # ES Module wrapper node Build.js gzip # gzip all dist/ files at level 9 node Build.js analyze # size, class count, SHA-256 report node Build.js manifest # generate dist/manifest.json
✔
Typical full release flow: haxe --run Build --release all followed by node Build.js all. The result is a versioned dist/hxjavascript-1.0.0.zip ready for haxelib publish, plus CJS/ESM/IIFE bundles with gzip variants and a signed manifest.
